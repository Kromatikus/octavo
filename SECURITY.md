# Security

Octavo is an experimental, homemade cipher made for learning and for fun. It is not constant-time, and nothing here is a proof of security. An independent reviewer ([@liqdmetal](https://github.com/liqdmetal), [issue #1](https://github.com/Kromatikus/octavo/issues/1)) rebuilt the round function and reported no distinguisher, forgery or key recovery; that is a negative experimental result, not expert cryptanalysis and not a proof.

**Do not use Octavo to protect real data.** Use a vetted, well-reviewed tool such as AES-GCM-SIV (RFC 8452), [age](https://age-encryption.org), or [libsodium](https://doc.libsodium.org).

Found a weakness? That's the point of publishing it. Please open an issue with a description and, ideally, a script that reproduces it. Credible findings get added to [ATTACKS.md](ATTACKS.md) with credit.


## The demo seed is public

`sneak1024-seed.txt`, the file `load_seed()` and every `seed=None` call use, is a **public demo seed**. Its full hex is published in `score/vectors.json` (and in every frozen snapshot), so any blob made with `seed=None` or with that file can be read by anyone. Use it only for samples and tests. Études refuse it (and `seed=None`) unless the handle is made with `etude(r, lab_seed=True)`.

## Timing side channels (Info 7, conductor's mark review)

Octavo is not constant-time. The 16-round function looks up keyed 256-entry S-box tables, uses a 64 KiB GF(2^8) multiplication table, uses data-dependent rotations in the bow-pressure layer (`r1` and `r2` come from a pressure byte), permutes cells with key-dependent indices, and builds its schedule with rejection sampling. Those operations can leak through cache timing and other microarchitectural side channels. CPython cannot be made constant-time: integers are objects, every index touches a value-dependent object, and the interpreter adds microseconds of jitter. The Python reference can only be made **uniform in control flow**. The deliberate constant-time primitives are `hmac.compare_digest` and OpenSSL-backed SHA-256 / HMAC.

What the conductor revision does:

- **Single-block rejects are equal-time (M1 fixed).** `decrypt()` (and `Etude.decrypt()`) always compute and compare both the commitment and the tag, combine the two results without short-circuit, and raise one `AuthError("authentication failed")`. A wrong key, wrong AD, bad commitment, bad pickup/nonce, bad ciphertext and bad tag all do the same work before rejecting. Before this change a commitment failure took about 8 µs and a tag failure about 24 µs; now both take the commitment-plus-tag time. No `Schedule` is ever built before both checks pass.
- **Movements rejects are equal-time too (conductor-polish, attack L1).** `decrypt_movements()` (and `Etude.decrypt_movements()`) always compute the commitment AND the coda (one HMAC over header, commitment, count, every ciphertext, every cadence and AD), combine the two results without short-circuit, and raise one `AuthError("authentication failed")`. Nothing is decrypted, and no cadence key or `Schedule` is derived, before both pass. Measured on a random seed (medians of 4,000 interleaved trials per class, `test_results.txt` and `conductorpolish_verification/`): before, commitment failure 4.84 µs vs coda failure 11.87 µs (3 movements, Welch t ≈ −628); after, 12.45 µs vs 12.42 µs (t ≈ 1.7); at 10 movements 5.22 vs 14.75 µs before (t ≈ −370), 14.70 vs 14.68 µs after (t ≈ 0.7). The cost: a forged blob with a stolen header now walks the body once (one HMAC, O(nmov), capped at MAX_MOVEMENTS), the same as a blob with a bad coda always did. Timing still grows with the (public) blob size.
- **Rehearsal rejects (rehearsal, format version 8).** Chunk 0 of a stream always computes and compares both the commitment and its chunk tag, combines them without short-circuit, and raises one `AuthError("authentication failed")`; later chunks check their own tag. No block of a chunk is decrypted before that chunk verifies, and within one `update()` call every chunk is verified before any is decrypted. The final-chunk padding is checked with a fixed-structure integer test, after the tag. A test compares commit-fail, tag-fail and ciphertext-fail medians on a one-chunk stream (the test allows 15%; measured runs agreed within 1%, about 15–17 µs each). Timing grows with the public stream length and chunk count.
- **Padding check is fixed-width (conductor L4, conductor-polish L3).** `_unpad_block` reads the 127 payload bytes as one integer, ORs in a fixed top bit and ANDs with a precomputed pad-region mask for `L & 127`, so every big-int operation has same-size operands. It is about 12× faster than the conductor per-byte loop (about 0.6 µs vs 7 µs) and its L=0 vs L=127 gap fell from about 780 ns to under 100 ns. It returns exactly the old rule's result (checked on every L 0–255 with every single-byte pad position and 200,000 random blocks).
- **Seed caches (conductor I3, conductor-polish I4/I5).** The default seed file is parsed once; the cache key is `(path, st_dev, st_ino, st_size, st_mtime_ns, st_ctime_ns)`, so replacing the file (new inode) or rewriting it in place (new ctime, which `cp -p`, `rsync -t` and `touch -r` cannot set back) forces a re-read. Seeds that passed the weak-seed rule are remembered in a 16-entry LRU (least recently used dropped, never a clear-all). Derived étude keys are never put in that memo; they are checked on every use. Within one process, timing of a memo miss vs hit can still show whether a seed was used recently.
- **Not changed in Python (port requirements below):** the secret-indexed S-box tables (M2), the GF(2^8) table (L1; a branch-free masked-doubling multiply is bit-identical and tested, but about 3× slower in CPython, so the table stays), data-dependent rotations (L2), schedule rejection sampling (L3) and key-dependent permutation addressing (L5).

## Rust port requirements

Anyone porting Octavo to Rust, C, Go or WASM must not copy the Python structure. A native port of the current design leaks clearly. Requirements:

1. **S-boxes (M2):** no 256-entry tables. Use a bitsliced or tower-field SM4 S-box circuit, and evaluate the keyed affine layers `A2·S(A1·x ⊕ b1) ⊕ b2` (and their inverses for SI/SI2) as constant-time bit-matrix products.
2. **GF(2^8) (L1):** no `_GF_MUL` table. Use masked `xtime` (`(a << 1) ^ (0xF5 & 0u8.wrapping_sub(a >> 7))`) and fixed-iteration schoolbook multiplication. The test suite checks that this is bit-identical to the table on all 65,536 inputs.
3. **Permutations (L5):** use SIMD byte shuffles (`pshufb`, `vpermb`, NEON `tbl`) with secret index vectors, or full-scan masked gathers. Replace the `if SH[f]` branch in `unweave` with an unconditional rotate.
4. **Rotations (L2):** `rotate_left` is constant-time on x86, ARMv7+ and AArch64. Exclude cores without a barrel shifter or use a masked rotate network.
5. **Schedule (L3):** fixed-budget derivation, no data-dependent loop counts: squeeze a fixed number of bytes, use wide modular reduction, build invertible matrices without rejection, and compute parity branch-free.
6. **Comparisons and padding (M1, L4):** use the `subtle` crate (`ConstantTimeEq`, `Choice`, `ConditionallySelectable`) for commitment, tag, cadence, coda and SIV checks and for the padding/length check. One combined `Choice` and one error return for single-block.
7. **Hygiene:** `zeroize` the seed and all derived keys and tables; use `black_box` / `#[inline(never)]` around constant-time selects.
8. **Verification:** dudect-style tests, Valgrind/ctgrind secret marking, and binary-level checks in CI.

## Format limits (Info 8)

Single-block messages are at most 127 bytes in a 228-byte version-6 blob (32-byte commitment plus 32-byte tag). Movements mode takes payloads up to 1,040,384 bytes (8,192 movements) in a version-7 blob with a 72-byte header. Rehearsal (version 8) streams have no fixed byte cap: chunk size is a multiple of 128 from 128 bytes to 1 MiB (default 64 KiB), at most 2^24 chunks per stream including the final chunk (1 TiB at the default size), and the same 65,536-byte AD cap. Associated data is authenticated — bound into the SIV nonce, the HMAC-U commitment, and the tag or coda, with an unambiguous length prefix — but is not stored in the blob, so the same AD must be supplied on decrypt. Minimum single-block overhead is 101 bytes (228 − 127).

Default `decrypt()` / `decrypt_movements()` accept only the current committing formats (v6/v7), and `decrypt_rehearsal()` / `RehearsalDecryptor` accept only v8. Any other version raises `UnsupportedVersion`, which is a `ValueError` but **not** an `AuthError`, so an `except AuthError:` handler cannot drift into a legacy fallback. Published v2/v3 blobs open only through `decrypt_legacy()` / `decrypt_movements_legacy()` with `allow_noncommitting=True`; those helpers are not key-committing, refuse without the flag, and emit `LegacyFormatWarning` on every call. Since conductor-polish that warning is a `UserWarning`, so Python's default filters show it even when a library module (not `__main__`) makes the call. The private bodies behind those helpers (`_decrypt_legacy_v2/_v3`, `Etude._decrypt_legacy_block/_movements`) check the flag, emit the warning and pin the version byte themselves, so calling them directly is gated the same way. Unpublished v4/v5 blobs are rejected. Commitment, tag, cadence and coda failures all raise `AuthError("authentication failed")`, so the error type does not distinguish a wrong key from wrong associated data. Offline seed confirmation is possible whenever the AD is known (same as for the tag).

Études (`etudes.py`, lab only) run under their own derived key (`StaffSponge(b"E", seed, rounds‖0…)`), hash their version byte into the SIV nonce, and open only blobs of their own round count, so an étude handle can no longer decrypt or share round material with a live blob.

Guessable seeds (all zeros, all `FF`, integer `1`, or fewer than 32 distinct nonzero bytes) are rejected. A broken or repeating OS generator cannot force two in-process encryptions to share a pickup.

## Reject classes and legacy fallback (conductor-polish)

Every reject a decrypt API raises for a bad or foreign blob is a `Rejected` (a `ValueError`): `AuthError` (authentication, length, prefix, movement count, SIV mismatch), `DecodeError` (valid tag, malformed block) and `UnsupportedVersion` (a format this API does not speak, including an étude round-count mismatch). Write `except Rejected:` to mean "this blob was not accepted". `AuthError` and `UnsupportedVersion` remain disjoint. Caller mistakes stay plain `TypeError` / `ValueError` (wrong argument types, a weak seed, a missing `allow_noncommitting=True`).

Do **not** build a legacy fallback as `except UnsupportedVersion: decrypt_legacy(...)`. The first byte is attacker-chosen, so that turns the non-committing downgrade into an attacker-selectable path. If an application must still read octavo009 blobs, use an explicit **allowlist** (for example the SHA-256 of each known legacy blob, or a stored per-record "legacy" flag set when it was written) and a hard **cutoff** date after which the fallback is deleted.

**Legacy end date.** `decrypt_legacy()`, `decrypt_movements_legacy()` and the legacy étude helpers (`Etude.decrypt_legacy` / `decrypt_movements_legacy`, bytes `0xE*`/`0xF*`) are deprecated. The legacy étude helpers will be removed in the first revision after the octavo010 freeze that touches `etudes.py`, and no later than 2027-03-01; the octavo009 étude score then opens only from the frozen octavo009 tree. `etude_key(seed, r)` is the deliberate, documented ungated low-level path (no demo-seed check); `Etude.lab_seed` is read-only after the handle is made.

## Rehearsal streaming (format version 8; attacked twice, fixes applied in rehearsal-fix and rehearsal-polish)

Rehearsal is a STREAM-style online AE mode (after Hoang, Reyhanitabar, Rogaway and Vizar, CRYPTO 2015) on the unchanged staff-core. It has had **three in-house attacks** (`attacks_octavo_rehearsal/`: no cryptographic break of v8; 1 Medium, 3 Low, 6 Info, mostly in the file helpers and API, fixed in **rehearsal-fix**; then `attacks_octavo_rehearsalfix/`: no cryptographic break; 2 Low, 9 Info in the file-commit code, workers and API, fixed in **rehearsal-polish**; then `attacks_octavo_rehearsalpolish/`: no cryptographic break; 3 Low, 9 Info in the corners of the file helpers, the warning and the workers, fixed in **rehearsal-finale**, frozen as octavo011). The finale fixes have not been attacked again, and there has been no outside review. Treat rehearsal as the least-reviewed part of a homemade cipher. For real streams use age (which is itself STREAM-based), libsodium's `crypto_secretstream`, or AES-GCM-SIV per chunk under a vetted framing.

- **Header (72 bytes):** `8 || SN2 || pickup(16) || nonce(16) || commit(32) || chunk_size(4)`. The commitment is `HMAC-SHA256(K_commit, U || 8 || SN2 || pickup || nonce || encode_ad(ad) || chunk_size32)`.
- **Chunks:** non-final `ct(chunk_size) || tag(32)`; final `ct(128·k) || tag(32)` with the last 0 … chunk_size−1 bytes padded `0x80 00…`. Per-chunk MAC key and block tweaks come from sponge domain `R` over `chunk || pickup || nonce || chunk_size32 || index64 || final8 || ad_digest`; blocks are `E(P ⊕ T) ⊕ T` under one per-stream `Schedule` whose nonce is `R` over `sched || pickup || nonce || chunk_size32 || ad_digest`, with `ad_digest = SHA-256(SN2/A || encode_ad(ad))`. The AD digest entered both inputs in rehearsal-fix (I1), which changed every v8 ciphertext; v8 had never been published, so there is no legacy v8 path. The chunk tag binds the clef, the rehearsal signature (domain `H`), version, magic, pickup, nonce, commitment, chunk size, index, final flag, an AD digest (`SHA-256(SN2/A || encode_ad(ad))`) and the chunk ciphertext.
- **What it rejects:** truncation at any offset (the last chunk present was sealed non-final), extension, reordering, duplication, dropping, cross-stream splicing (pickup, nonce and chunk size are in every chunk key), chunk-size rewrites (commitment and chunk keys), wrong AD and wrong seed. All of these raise `AuthError`; a foreign version byte raises `UnsupportedVersion`.
- **Release rule:** `RehearsalDecryptor.update()` returns plaintext only for chunks whose tag has verified, and it holds back the last `chunk_size + 32` bytes until it knows whether they are the final chunk. **A stream cut early therefore yields a verified, chunk-aligned prefix, and the error arrives only at `finalize()`.** An application that must not act on a prefix should buffer until `finalize()` succeeds, or use `iter_rehearsal()`, which always runs `finalize()` and so raises `AuthError` from the loop on any cut, including one exactly at a chunk boundary. Leaving a `with RehearsalDecryptor(...)` block normally without `finalize()` raises `AuthError("stream not finalized")`, and a decryptor dropped in that state emits an `UnfinalizedStreamWarning` (rehearsal-polish L2: a `UserWarning`, shown by Python's default filters; it was a hidden `ResourceWarning`; rehearsal-finale L2: shown for every dropped decryptor through an appended `always` filter, and under `-W error` reported through `sys.unraisablehook` instead of being swallowed). A destructor warning cannot make the program fail, and it arrives only at garbage collection, so **a bare `update()` loop without `finalize()` still returns a verified prefix of a cut stream with no exception**: use `iter_rehearsal()`. Consumers of `iter_rehearsal` that stop early (`break`, `islice`, `zip`) also hold only a verified prefix. `decrypt_rehearsal()` is all-or-nothing and checks every tag, the final chunk's included, before decrypting anything, so a forged final chunk costs HMACs only. The streaming decryptor and `decrypt_rehearsal_file()` still find a forged final chunk only at the end, after decrypting the verified chunks before it: they keep memory bounded, so replaying a captured stream with its last byte flipped still costs the receiver a full decryption. After any reject the decryptor is dead. On a bad final padding (only a seed holder can build such a stream) the decrypted chunks are cleared before `AuthError` is raised, so no plaintext is reachable from the traceback (rehearsal-finale I8). `iter_rehearsal` treats a `bytes` src as ciphertext and never consults the filesystem for it (rehearsal-finale L3; the rehearsal-polish bytes-path guard was a file-existence oracle).
- **File helpers (rehearsal-fix M1, L1, L2; rehearsal-polish L1, I3–I6; rehearsal-finale L1, I1–I4, I7).** src and dst paths are made absolute when the call starts, and dst's directory is opened once; every create, link, rename, stat and unlink is relative to that directory fd (a `chdir` or swapped parent symlink mid-call cannot move the output). Output goes to an anonymous `O_TMPFILE` in dst's directory (mode 0600; no name to swap, nothing left by a crash mid-stream), or, where that is unavailable, a unique dot-name made `O_CREAT | O_EXCL | O_NOFOLLOW` (0600). It is fsync'd, then published by a hard link that never follows a symlink (`linkat` of `/proc/self/fd/N`, or `follow_symlinks=False`) and fails if dst exists; `overwrite=True` onto a missing dst links directly, and onto an existing dst links to a fresh `.swap` name and swaps it with dst atomically (`renameat2(RENAME_EXCHANGE)` on Linux; if dst is then not our inode it swaps back, so a refused race keeps the old dst; elsewhere `os.replace`, where a refused race can cost the old dst). **A crash during an `overwrite=True` commit can leave a 0600 `.<dst>.XXXXXXXX.swap` file** holding the new plaintext or the old dst; clean up stale `.*.swap` / `.*.tmp` / `.*.partial` dot-files after a crash. **After publishing, dst must be the very inode this call wrote** (`lstat` against the open descriptor); otherwise the name this call created is removed and `RuntimeError` is raised, so the helper never vouches for a substituted file (the rehearsal-fix commit race, L1). Then the directory is fsync'd. No fixed sibling name is opened, truncated or deleted; only the call's own temporary file is ever unlinked, and only while it is still the same inode. A symlink at dst is never followed. An existing dst raises `FileExistsError` unless `overwrite=True` (which must be a real `bool`; it replaces read-only files too, the result is 0600, and other hard links to the old dst keep the old content). Only `EPERM`, `EOPNOTSUPP`/`ENOTSUP`, `ENOSYS`, `EXDEV` and `EMLINK` from the link mean "no hard links here"; then dst is created `O_EXCL | O_NOFOLLOW` and the bytes are copied in (never clobbering a file created in the gap), and the copy's descriptor stays open through the inode check and until the call returns, so its inode number cannot be recycled for a substitute (rehearsal-finale L1). On the named-temp path any other link error is raised; on the `O_TMPFILE` path any link failure (odd `/proc`, hidepid, sandboxes) falls back to the copy, so verified output is not lost (rehearsal-finale I3). The same-file check is repeated relative to the directory fd and just before publishing (rehearsal-finale I4). `read_size` must be an int ≥ 1 (I7). The temp prefix is cut to 100 bytes at a whole UTF-8 character, so long non-ASCII names work. **dst's directory should not be writable by other users (or should be sticky):** such a user can still replace or delete dst after the call returns. src and dst being one file (realpath, or `(st_dev, st_ino)` through a symlink, hard link or descriptor) raises `ValueError` before anything is written. A file-object dst is buffered in an anonymous 0600 temporary file (in the system temp directory, so plaintext does touch disk there) and gets nothing until the stream verifies, unless `stream_verified_prefix=True`. `keep_partial=True` (a real `bool`) keeps the verified prefix, fsync'd and with its directory fsync'd, as `dst.partial` if that name can be created (published and inode-checked like dst, never clobbered), else, on any error (taken, name too long, refused race), under a fresh unique dot-name, reported as the absolute `exc.partial_path` (if keeping fails altogether, the reason is `exc.partial_error`); a stream that fully verified but could not be published is kept as `dst.complete`; nothing is kept when no chunk verified, and `keep_partial` has no effect for a file-object dst. With `O_TMPFILE` a SIGKILL mid-stream leaves nothing; on the named-temp fallback it can leave a 0600 dot-file holding verified prefix plaintext. Not covered: an attacker who can already write to dst's directory can still delete or rename entries there, and the helpers do not lock the source against concurrent changes.
- **Receiver limit (I4).** `max_chunk_size` (on `RehearsalDecryptor`, `decrypt_rehearsal`, `iter_rehearsal` and `decrypt_rehearsal_file`; default `None`, any valid size) rejects a header declaring a larger chunk size before anything is buffered. Without it, a forged header can still make the receiver buffer and HMAC up to 1 MiB + 32 bytes before the first reject. It stays opt-in. One-shot `decrypt_rehearsal` peaks at about 4× the blob for a genuine stream (5× at chunk size 128) on top of the caller's copy, and `encrypt_rehearsal` at about 2× the message; use the streaming reader or the file helpers for large data.
- **Not misuse-resistant:** there is no SIV nonce. Pickup and nonce are 32 fresh bytes per stream (hashed `urandom`, time, counter and pid), and a repeated pair under the same seed **and the same AD** would reuse every chunk key and tweak: equal blocks at equal positions show, and chunks with the same index can be swapped between the two streams (both forgeries open). Since rehearsal-fix, a repeat under a different AD gives unrelated blocks. Making chunks misuse-resistant (SIV-style per chunk) would be new design work and is not done.
- **Attestation:** v8 does not move `EXPECTED_MIX_SHA256` or `key_sig` (rehearsal code is not reachable from `MIX_CODE_ROOTS`, which keeps v6/v7 byte-identical). It has its own `EXPECTED_REHEARSAL_SHA256` over the code and data reachable from `REHEARSAL_CODE_ROOTS` (the whole staff-core included) plus the live mix digest, and a seed-keyed `rehearsal_signature` in every chunk tag. The same source-attestation limits apply. Because the rehearsal digest covers all v8 API code (file helpers and workers included), the rehearsal-polish edits moved it (`dd02f707…`) and so `rehearsal_sig` and every v8 tag; v8 headers and ciphertext blocks did not change. Since rehearsal-polish the module source is read once at import and primed into `linecache`, so the attestations hash those source bytes. That did **not** prove the parent executed them: Python runs a cached `.pyc` whenever its recorded source mtime and size match, so a `.pyc` built from a same-size modified source passed both attestations (rehearsal-polish attack I5). Since rehearsal-finale the import also compiles `_MODULE_SOURCE` and requires every function and method of the module to have exactly that code object, so such a `.pyc` (or a `.py` swapped between Python's read and the snapshot) fails the import. Module-level statements are not compared; anyone who can write the install can still change what runs.
- **Workers (rehearsal-fix I2; rehearsal-polish I1, I2; rehearsal-finale I6):** `workers=N` is capped at `min(32, os.cpu_count())`. Batches of already-verified chunks go to fresh worker interpreters (`python -I -B -S -c …` via `subprocess` with an empty environment since rehearsal-finale I6, never a fork), started lazily, at most one per chunk in the batch. **Workers are part of the trusted base.** Since rehearsal-polish a worker does not read `sneak_n2.py` from disk: the parent sends the module source it read once at import over the pipe, the worker executes those bytes, and it answers `sha256(source) || rehearsal digest`. That hello is only a pipe/version sanity check, not a proof; what protects you is that the code comes from the parent, so a module file replaced after import is never run. Since rehearsal-finale, `-S` skips `site` (no `.pth` file runs in a worker) and the environment is empty (no `LD_PRELOAD`/`LD_LIBRARY_PATH`; on Windows only `SYSTEMROOT`), and the parent recomputes one random block per batch and kills the workers on a mismatch (`RuntimeError`): a spot check that catches a worker returning wrong blocks with probability (wrong blocks)/(blocks in the batch) per batch, not a proof. Still trusted and not checked: `sys.executable` (it is executed with the worker argv and receives the public module source), the interpreter and the stdlib. A worker receives the stream's `Schedule` round material and tweak-masked blocks, never the seed, the AD or AD digest, the commitment key or a MAC key. It is **not** true that it never sees plaintext-derived data: a worker transcript plus the public ciphertext gives the plaintext (`P = X ⊕ C ⊕ Y`), and an all-zero plaintext block reaches the worker as that block's tweak verbatim. The round material is secret for that one stream, so a compromised worker process compromises that stream. Every frame to and from a worker has a deadline (`worker_timeout`, default 600 s per hello or chunk); a worker that misses it is SIGKILLed and reaped and the call raises `RuntimeError`, which leaves a decryptor dead like a reject (it does not mean the stream was forged). `multiprocessing` spawn and forkserver were not used because they re-run an unguarded caller `__main__` in each worker. Workers exit on `finalize()`, a reject, `close()` or garbage collection. Output is byte-identical to `workers=1`.
- **Études** have no streaming mode.
