## Stage 2: 8-stroke bow (format change), OHLO's choice
- **Bow** = strokes `(2,3,4)(5,7,1)(0,7,3)(4,7,6)(1,6,0)(1,7,2)(2,5,4)(0,3,1)`, pressure rotations all 0. 8 strokes (was 7).
  Full structural diffusion in **both** directions: every beat reaches every beat forward and inverse
  (old bow: neither direction full; inverse beat 7 reached only 6, 7). Empirical min P(bit flip in beat k changes beat m): fwd 0.79, inv 0.63.
- Search (`lab/bow_*.py`, `lab/bow_cand.py`): no reordering of the old strokes, no single inserted stroke, and no 7-stroke list in 300k random samples works.
- **Choice:** a 10-stroke **sawtooth bow** (ramp `(0,1,2)…(6,7,0)` + snap `(7,4,3)(3,2,5)(1,0,2)`) was also built, at OHLO's request. It has equal diffusion, bound
  and attack results but costs 2 more strokes. On about 10:35 AM ET OHLO chose the 8-stroke bow for its speed. The sawtooth code, vectors and report are kept in `lab/sawtooth10`.
- All five backends (avx512gfni, avx2gfni, avx2, portable, table) and the Python reference use the 8-stroke table. `vectors/fix1_vectors.json`
  (from the Python reference) matches all five backends bit-exactly. The AEAD vectors were regenerated by the independent Python AEAD and match Rust.

## Stage 3: SN3C/ AEAD "N3-SIV" (`rust/src/aead.rs`, spec §5.3)
- KDF → separate MAC and ENC N3 instances; CMAC over 128-byte blocks (GF(2^1024) doubling, x^1024+x^19+x^6+x+1, irreducibility checked);
  S2V over [header, AD, nonce, M]; 256-bit tag = V[0..32]; CTR keyed by the tag with batch-64 keystream.
- Blob: `SN3C/ ‖ 0x1B ‖ nonce16 ‖ tag32 ‖ ciphertext` (54-byte overhead, |M| ≤ 2^30). Strict parser, typed errors, no panics.
- Constant-time 32-byte compare (branch-free, verified in disassembly); plaintext wiped on failure.
- Independent Python implementation (`tools/aead_ref.py`, from the spec) generated `vectors/aead_fix1_vectors.txt`. Rust matches it.
- Lab CLI `n3aead seal|open` (errors → exit 1/2, no panics). Throughput ≈ 27 MiB/s seal or open (sequential CMAC dominates; PMAC would parallelize).
- Honest claims: SIV-style misuse resistance **if N3 is a strong PRP** (unproven); nonce reuse reveals only identical (AD, nonce, M);
  forgery ≈ 2^-256 per try; birthday limits come from the 256-bit tag (stay well below 2^100 messages/key), not the 1024-bit block.
  Not key-committing; no external review.

## Caveats
- In-house analysis only. The trail bound treats the bow as free and samples 2 bridge schedules. The AEAD security argument assumes N3 is a good PRP.
- AVX2 paths were forced on an AVX-512 box. ARM was not run. dudect can show a leak but cannot prove there is none.
- The SNAPSHOT*.md files in this folder describe 003, not fix1.

Octavo is still homemade; for real secrets use AES-GCM-SIV, age, or libsodium.
